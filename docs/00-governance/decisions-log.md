# Decisions Log

## Cómo usar este registro
Documentar decisiones relevantes del proyecto con fecha, contexto, decisión e implicaciones.

## Decisiones iniciales

### D-001 - Inicio del proyecto como captador de leads legales inmobiliarios
- Fecha: 2026-04-28
- Estado: Aprobada
- Contexto: Se requiere validar demanda y construir una base operativa antes de invertir en una plataforma más amplia.
- Decisión: El proyecto inicia como captador de leads para servicios legales inmobiliarios.
- Implicaciones:
  - La primera experiencia del usuario estará orientada a captar interés y datos del prospecto.
  - El valor principal inicial será filtrar casos viables para revisión profesional.

### D-002 - Primer vertical enfocado en regularización de inmuebles
- Fecha: 2026-04-28
- Estado: Aprobada
- Contexto: Se necesita un punto de entrada claro, con necesidad frecuente y buena afinidad con servicios legales posteriores.
- Decisión: El primer vertical será regularización de inmuebles.
- Implicaciones:
  - La narrativa inicial, formularios y filtros deben girar alrededor de regularización.
  - Los demás servicios se manejarán como líneas relacionadas o expansiones futuras.

### D-003 - Uso de marca comercial propia
- Fecha: 2026-04-28
- Estado: Aprobada
- Contexto: Conviene construir una marca escalable, flexible y menos dependiente del nombre personal del abogado.
- Decisión: Se trabajará con marca comercial propia, no necesariamente con el nombre personal del abogado.
- Implicaciones:
  - Branding, dominio y mensajes deben diseñarse como activo comercial independiente.
  - La credibilidad del abogado se integrará como respaldo experto, no como única base de marca.

### D-004 - Rol del abogado como especialista revisor de casos calificados
- Fecha: 2026-04-28
- Estado: Aprobada
- Contexto: Es importante controlar calidad del servicio y evitar aceptar casos sin revisión.
- Decisión: El abogado operará como especialista legal que revisa y atiende casos calificados.
- Implicaciones:
  - No debe prometerse aceptación automática de casos.
  - El flujo operativo requiere pre-filtro antes de atención formal.

### D-005 - Entorno inicial de trabajo y validación antes de publicar
- Fecha: 2026-04-28
- Estado: Aprobada
- Contexto: Se busca iterar con seguridad antes de mover cambios a un entorno productivo.
- Decisión: El desarrollo se hará primero en VPS de agentes/OpenClaw y después se validará antes de publicar en VPS productivo.
- Implicaciones:
  - El repositorio actual funcionará como espacio controlado de definición y construcción inicial.
  - Deben existir revisiones explícitas antes de despliegues públicos.
